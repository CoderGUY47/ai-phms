📑 Project Proposal & Assessment Specification
Project Name: AI-Powered Prescription & Health Analytics Management System
1. Project Overview
This project is a modern web application designed to help patients organize their medical history and help doctors make faster, safer clinical decisions.
The application works by allowing patients to upload pictures or PDFs of their past prescriptions and medical test reports. An AI Engine (like Google Gemini or OpenAI) will automatically read these documents, extract critical medical information, and organize it into a structured timeline.
2. Target Tech Stack
You must build this application using only the frontend tech stack specified below:
Framework: Next.js (App Router preferred)
Language: TypeScript (for type safety and clean interfaces)
Styling & UI Components: Tailwind CSS combined with Headless UI libraries (such as Shadcn UI or HeroUI)
AI Integration: Gemini API or OpenAI API SDK (invoked directly from Next.js Client or Server Actions)
Data Persistence: Browser localStorage and React State Management (No external database required for this frontend assessment)
3. Core System Portals & Features
🟢 Portal 1: Patient Portal
This portal is the gateway for patients to manage their health documents.
Document Upload Center: A clean drag-and-drop zone supporting PDF files and image formats (PNG, JPEG).
AI Processing & Extraction Engine:
Once a document is uploaded, it is sent to the AI API.
The AI must extract and structure the data into the following format:
Doctor Name and Consultation Date
Patient Case/Symptoms Summary
Structured Medicine List (Name, Dosage, and Duration)
Classification of Medicines: Antibiotics, Vitamins, Calcium, Gastric Medicine, etc.
Vital Signs: Respiratory Rate (RR), Blood Pressure (if available).
Structured Test Results: Test names matched with their numerical values.
Local Ledger Storage: The generated AI summary must be saved securely inside the browser's localStorage, organized cleanly date-wise.
🔵 Portal 2: Doctor Portal
This portal allows medical professionals to view a patient's historical health metrics cleanly before a consultation.
Patient Search Index: Doctors can search for any patient instantly using a unique Patient ID.
Lifetime Health Summary Dashboard: Once a patient is selected, the doctor is presented with an analytics dashboard featuring:
Antibiotic Tracker: A dedicated section displaying total lifetime usage, classification types, and historical dates of consumption.
Medication Categorization Blocks: Separate, scannable UI tabs or cards grouping historical data for Vitamins, Calcium, and Gastric Medications.
Diagnostic Test History: A clean chronological chart or table showing past test results to monitor changes over time.
Deep-Dive Details View: A button to expand and read the complete, original breakdown of any single consultation date.
🔴 Portal 3: Admin Portal
This portal provides high-level control over system behaviors.
Patient & Doctor Profile Directory: Ability to view, mock-register, suspend, or delete patient and doctor access IDs.
System Audit Logs: A basic dashboard view to monitor how many documents have been successfully parsed by the AI engine.
Mock Variables Configuration: Settings panel to clear localStorage or inject pre-made mock patient datasets for quick evaluation.

You must define strict TypeScript interfaces for your data structures. Example template structure:
export interface MedicalRecord {
  recordId: string;
  date: string;
  doctorName: string;
  patientCase: string;
  respiratoryRate: string;

4. Data Logic Execution
Implement a robust system tool to check for existing records inside localStorage, append new entries, and read them flawlessly on the Doctor UI portal without page crashes.
